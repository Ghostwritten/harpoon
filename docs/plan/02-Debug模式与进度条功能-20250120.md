# 添加 Debug 模式和进度条功能

## 概述

添加 `--debug` 参数显示详细的错误信息，并实现美观的进度条来显示 pull/push/save/load 等操作的进度，提升用户体验和可观测性。

## 核心需求

1. **Debug 模式**：添加 `--debug` 参数，显示底层命令的完整输出（stdout/stderr）
2. **进度条**：为 pull/push/save/load 操作添加美观的进度显示
3. **错误详情**：在 debug 模式下显示完整的错误堆栈和底层命令输出

## 实施计划

### 1. 添加 Debug 参数和全局状态

**文件**: `cmd/hpn/root.go`

- 添加 `debug` 全局变量
- 在 `init()` 中添加 `--debug` 标志
- 创建全局 debug 状态管理函数

### 2. 选择进度条库

**推荐库**: `github.com/vbauerster/mpb/v8` (多进度条支持) 或 `github.com/schollz/progressbar/v3` (简单易用)

**选择标准**:

- 支持多进度条（并行操作）
- 美观的终端输出
- 活跃维护
- 轻量级

### 3. 扩展 Runtime 接口

**文件**: `internal/runtime/interface.go`

- 在 `PullOptions` 中添加 `Debug bool` 字段
- 在 `PushOptions` 中添加 `Debug bool` 字段
- 在 `SaveOptions` 中添加 `Debug bool` 字段

### 4. 更新 Runtime 实现以支持 Debug 和进度

**文件**: `internal/runtime/docker.go`, `podman.go`, `nerdctl.go`, `skopeo.go`

#### 4.1 Pull 方法改进

- 当 `options.Debug == true` 时，捕获并输出完整的 stdout/stderr
- 对于支持进度输出的命令（docker/podman），实时显示进度
- 使用 `cmd.Stdout` 和 `cmd.Stderr` 捕获输出

#### 4.2 Save 方法改进

- 当 `options.Debug == true` 时，显示详细保存信息
- 对于大文件，显示传输进度（通过监控文件大小变化）

#### 4.3 Push 方法改进

- 类似 Pull 方法，支持 debug 输出和进度显示

### 5. 实现进度条管理器

**文件**: `internal/progress/progress.go` (新建)

- 创建进度条管理器，支持多进度条
- 为每个操作（pull/push/save/load）创建进度条
- 实现进度更新逻辑

**功能**:

- 多进度条支持（并行操作）
- 自动计算百分比和速度
- 美观的终端输出（支持颜色和动画）

### 6. 更新 Pull 操作以使用进度条

**文件**: `cmd/hpn/root.go`

- 在 `executePull()` 中初始化进度条管理器
- 在 `pullImageWithRetry()` 中更新进度条
- 在 debug 模式下显示详细错误信息

### 7. 更新 Save 操作以使用进度条

**文件**: `cmd/hpn/root.go`

- 在 `executeSave()` 中初始化进度条管理器
- 在 `saveImage()` 中显示保存进度
- 监控文件大小变化来更新进度

### 8. 更新 Push 和 Load 操作

**文件**: `cmd/hpn/root.go`

- 类似 Pull 和 Save，添加进度条支持
- 在 debug 模式下显示详细输出

### 9. 错误处理增强

**所有 Runtime 实现**

- 捕获命令的完整输出（stdout + stderr）
- 在 debug 模式下，将完整输出附加到错误信息中
- 提供更友好的错误消息

## 技术细节

### Debug 模式实现

```go
// 伪代码示例
if debug {
    var stdout, stderr bytes.Buffer
    cmd.Stdout = io.MultiWriter(os.Stdout, &stdout)
    cmd.Stderr = io.MultiWriter(os.Stderr, &stderr)
    
    err := cmd.Run()
    if err != nil {
        return fmt.Errorf("command failed: %v\nStdout:\n%s\nStderr:\n%s", 
            err, stdout.String(), stderr.String())
    }
}
```

### 进度条实现

- Docker/Podman 原生支持进度输出

**Save/Load 操作**:

- 监控文件大小变化
- 计算传输速度

## 测试要点

1. **Debug 模式测试**：

   - 验证 debug 模式下显示完整错误信息
   - 验证非 debug 模式下错误信息简洁

2. **进度条测试**：

   - 验证单镜像操作的进度显示
   - 验证多镜像并行操作的进度显示
   - 验证进度条在终端中的显示效果

3. **错误处理测试**：

   - 验证网络错误时的详细输出
   - 验证权限错误时的详细输出
   - 验证镜像不存在时的详细输出

## 注意事项

1. **性能考虑**：进度条更新频率不要太高，避免影响性能
2. **终端兼容性**：确保进度条在不同终端中正常显示
3. **非交互式终端**：检测是否为 TTY，非交互式时禁用进度条
4. **依赖管理**：选择合适的进度条库，确保轻量级和活跃维护
